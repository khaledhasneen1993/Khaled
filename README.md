# Cascade Hunter Khaled

النسخة الأساسية المعتمدة: **3.0.0-FINAL-EDGE**، بتاريخ **3 نوفمبر 2026**. محاكاة ورقية ببيانات Binance USDT-M المباشرة. أمر التشغيل الأساسي هو `bash run_dashboard.sh` للوحة Termux المحلية.

## الإعدادات المعتمدة

| الإعداد | القيمة |
|---|---|
| الرصيد الابتدائي للجلسة الجديدة | 100 USDT افتراضي |
| هامش الصفقة | 10% من رصيد المحفظة قبل الدخول، مع تقريب الكمية لدقة السوق |
| الرافعة | 50× |
| أقصى المراكز المفتوحة | 4 |
| وقف الخسارة | −8% من سعر تنفيذ الدخول |
| تفعيل التريل | +1.5% من سعر الدخول |
| مسافة التريل | 0.6% خلف أفضل سعر مرصود منذ التفعيل |
| شرط الحركة | تتجاوز ±1.2% بين الإغلاق الحالي وإغلاق قبل دقيقتين |
| شرط الحجم | أكبر من 3.5× متوسط الشموع `[-15:-3]` |
| ضغط دفتر الأوامر | أكبر من 0.35 للشراء، وأقل من −0.35 للبيع |
| قائمة المراقبة | أعلى 40 عقدًا مؤهلًا بالسيولة، بحجم يومي أدنى 15 مليون USDT |
| متابعة الإشارات | مستمرة بتحديثات WebSocket |
| تحديث قائمة العملات | كل 600 ثانية؛ ليس انتظارًا بين فحوص الإشارات |
| مراقبة الخروج | كل 8 ثوانٍ |
| تبريد الدخول للعملة | 8 ثوانٍ |
| الرسوم الافتراضية | 0.05% لكل تنفيذ |

الإعدادات المعتمدة في `baseline.json`، والقيم التنفيذية في `binance_cascade_hunter_dynamic_v2.py`. الرصيد 100 USDT يعطي هامشًا مستهدفًا 10 USDT وقيمة اسمية 500 USDT قبل التقريب. الرصيد 120 USDT يعطي هامشًا مستهدفًا 12 USDT. يُرفض الدخول عندما يعجز الهامش الحر عن تغطية الهامش والرسوم.

يُقاس الوقف من سعر تنفيذ الدخول. عند رصد حركة +1.5% لصالح المركز يتفعّل التريل ويلاحق أعلى سعر للشراء أو أدنى سعر للبيع. يضيق الوقف فقط، وعند لمسه يُغلق المركز كاملًا بسبب `SL` أو `TRAILING_SL`. كل رمز له مركز واحد كحد أقصى.

قوة الإشارة هي حاصل ضرب القيمة المطلقة للحركة في مضاعف الحجم والقيمة المطلقة لاختلال الدفتر. الحد الأدنى 0.020. عند خروج بصافي خسارة بعد الرسوم، ينتظر الرمز 600 ثانية قبل دخول جديد.

## تشغيل Final وKhaled فقط على لوحة تيرمكس

من داخل Ubuntu في Termux، بعد إيقاف اللوحة إن كانت تعمل:

```bash
cd ~/Khaled
git pull --ff-only origin main
bash run_dashboard.sh --fresh
```

التثبيت الأول: `git clone https://github.com/khaledhasneen1993/Khaled.git ~/Khaled`.
يلزم Python 3.11+ مع venv وGit. يثبت السكربت الاعتماديات، ويجلب مصدر Final main في نسخة محلية منفصلة داخل `.runtime/repos/Final`، ثم يفتح نفس واجهة المتابعة المحلية على **http://127.0.0.1:8787**. لا يحتاج رمز لوحة سحابية.

- `--fresh`: حسابان مستقلان، كل منهما 100 USDT وصفر مراكز وتنفيذات عند البداية؛ تُحفظ الجلسات السابقة دون حذف.
- `bash run_dashboard.sh`: يستأنف آخر جلسة مختارة ورصيدها ومراكزها. يقبل الاستئناف جلسات Final-Edge v3 المتوافقة. للانتقال من إصدار سابق استخدم `--fresh`، وتبقى ملفات الجلسات السابقة متاحة للتصدير.
- Ctrl+C يوقف البوتين ويحفظ حالتيهما؛ أزرار اللوحة توقف أو تستأنف كل بوت منفصلًا.
- Final يعمل بإعداداته الأصلية؛ Khaled يعمل بإعداداته المذكورة أعلاه. لم يتغير مصدر Final.
- التصدير يشمل سجل التنفيذات والصفقات المغلقة ولقطات الحالة بصيغتي CSV وJSON.
- كل عملية تحمل مصدرًا مستقلًا وملف حالة مستقلًا؛ اختيار الجلسة محفوظ في `.runtime/dashboard-accounts.json`.
- إن كان المنفذ 8787 مشغولًا، أوقف العملية التي تستخدمه قبل التشغيل.

لإبقاء الجلسة متاحة عند إغلاق الطرفية: شغّل `tmux new -s final-khaled` داخل Ubuntu قبل أمر التشغيل؛ للفصل Ctrl+B ثم D، وللعودة `tmux attach -t final-khaled`.

فحص واجهة التحكم: `python -m unittest discover -s dashboard/tests -v`.

## تفاصيل الصفقات والتصدير

اللوحة تعرض الجلسات، والرصيد، وقيمة المحفظة، والمراكز المفتوحة، وأسعار وأوقات الدخول والخروج، والكمية والرسوم والربح، وسبب الدخول والخروج. يمكن تنزيل الصفقات بصيغة CSV.

يحفظ السجل قياسات الحركة والحجم وضغط الدفتر عند الدخول، وسبب `SL` أو `TRAILING_SL` وسعر الرصد عند الخروج. سعر تنفيذ المحاكاة يُجلب منفصلًا وقد يختلف عن سعر الإشارة أو رصد الخروج. صافي الصفقة المغلقة يطرح رسوم الدخول والخروج معًا؛ ربح المركز المفتوح غير محقق. تظهر قياسات السجلات القديمة التي لم تُحفظ كبيانات غير متوفرة.

## التشغيل المحلي الاختياري

لتشغيل Khaled منفردًا داخل Ubuntu:

```bash
cd ~/Khaled
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -u binance_cascade_hunter_dynamic_v2_paper.py --state paper_state_final_edge_v3.json
```

هذا الأمر يستعيد `paper_state_final_edge_v3.json` تلقائيًا إن وُجد. يمكن تحديد ملف مختلف باستخدام `--state`. خيار `--reset` يستبدل حالة الملف المختار بحساب جديد؛ لا تستخدمه لاستعادة محاكاة سابقة.

## تنظيم المشروع

| الملف | الدور |
|---|---|
| `run_dashboard.sh` و`dashboard/` | تشغيل الحسابين واللوحة المحلية والتصدير |
| `binance_cascade_hunter_dynamic_v2_paper.py` | تشغيل Khaled منفردًا |
| `binance_cascade_hunter_dynamic_v2.py` | منطق الاستراتيجية وإعداداتها |
| `continuous_scanner.py` | الإشارات المستمرة وتحديث قائمة العملات |
| `paper_runtime.py` | دورة التشغيل وربط الاستراتيجية بالمحاكاة |
| `paper_account.py` | التنفيذ الافتراضي والرصيد وحفظ الحالة |
| `baseline.json` | تعريف النسخة والإعدادات المعتمدة |
| `tests/` | اختبارات النسخة الأساسية |

## الاختبارات وحدود المحاكاة

```bash
python -m unittest discover -s tests -v
python -m unittest discover -s dashboard/tests -v
```

الاختبارات تستخدم بيانات وخدمات وهمية للتحقق من المنطق والحفظ والرفع؛ ليست نتائج تداول أو اختبارًا تاريخيًا. لا يحاكي النموذج التصفية أو هامش الصيانة أو التمويل أو الانزلاق. وقف 8% هو نسبة **السعر**. التنفيذ ورقي بسعر السوق المرصود وقد يتجاوز مستوى الستوب بسبب الفجوات وتأخير الرصد. يتطلب استمرار المحاكاة بقاء تيرمكس والاتصال بالسوق قيد التشغيل.
