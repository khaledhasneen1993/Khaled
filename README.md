# Khaled — Cascade Hunter 2.1.0

بوت محاكاة ورقية لحظية على بيانات Binance USDT-M، مع TP/SL متكيفين حسب ATR، وBreakeven وTrailing. لا يرسل أوامر تداول حقيقية. هذه النسخة مستقلة عن ريبو `Final`.

**حالة التحقق:** نجحت اختبارات التنفيذ وفحص حسابات الخروج على ثلاثة أشهر من شموع BTC/ETH. لم يكتمل Backtest مطابق لإشارات الدخول الأصلية، ولذلك لم تُثبت أهداف الربحية وSharpe وDrawdown. التفاصيل في [تقرير التحقق](reports/TP_SL_REPORT.md).

## الإعدادات الحالية

| الإعداد | القيمة |
|---|---|
| رصيد جلسة جديدة | 100 USDT افتراضي |
| هامش الصفقة | 10% من رصيد المحفظة |
| الرافعة | 50× |
| أقصى المراكز المفتوحة | 3 |
| ATR | 14 فترة، من شموع الدقيقة |
| الوقف المبدئي | الأكبر من ATR × 1.5 و0.8% من سعر التنفيذ، ثم يُقص حسب حدود التصفية والمخاطرة |
| أقصى مخاطرة مخططة للصفقة | 3% من equity، شاملة رسوم الدخول والخروج |
| الهدف | الأكبر من ATR × 2.5 ومسافة الوقف النهائية × 1.5 |
| الحد الأدنى لـR:R | 1.5 |
| Breakeven | بعد حركة مواتية 0.6%، بإزاحة 0.1% أو ما يغطي الرسوم إذا كان أكبر |
| Trailing | بعد تفعيل Breakeven، بمسافة 1.2×ATR؛ لا يرخّي الوقف |
| الرسوم الافتراضية | 0.05% لكل تنفيذ |
| فحص الخروج | كل 8 ثوانٍ |

الإعدادات في [baseline.json](baseline.json). أُزيلت إعدادات الوقف والهدف الثابتين المستبدلة. تبقى معادلات الدخول وحجم الصفقة والرافعة كما هي: حركة تتجاوز ±1.2% خلال دقيقتين، وحجم أكبر من 3.5× المتوسط، ودفتر أوامر أول 20 مستوى بضغط أكبر من 0.35 للشراء أو أقل من −0.35 للبيع. المراقبة مستمرة، والتبريد 8 ثوانٍ، وقائمة أعلى 40 عقدًا تُحدَّث كل 600 ثانية بحد سيولة يومية 15 مليون USDT.

**أولوية حدود الوقف:** هامش 10% ورافعة 50× يجعلان وقف 0.8% يعادل خسارة 4% من الرصيد قبل الرسوم. لهذا يتقدم سقف المخاطرة 3% على الحد المبدئي 0.8%، ويكون الوقف النموذجي نحو 0.5% مع الرسوم الافتراضية. لا يتغير حجم الصفقة أو الرافعة.

## التثبيت أو التحديث

داخل أوبونتو/تيرمكس، من نسخة الريبو المحلية:

```bash
cd ~/Khaled
git pull --ff-only
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

يتطلب Python 3.11 أو أحدث. إن كان البوت يعمل، أوقفه بـCtrl+C قبل تحديث الملفات. استخدم المسار الفعلي لمجلد الريبو إذا كان مختلفًا.

## التشغيل المحلي دون لوحة

```bash
cd ~/Khaled
source .venv/bin/activate
python -u binance_cascade_hunter_dynamic_v2_paper.py --state paper_state_khaled.json
```

ينشئ حسابًا جديدًا إذا لم يوجد ملف الحالة، ويستعيد الملف نفسه إن وُجد. يحتفظ بالمراكز وحالة Breakeven وTrailing والسجل. أوقفه بـCtrl+C للحفظ والخروج. لا تشغّل عمليتين على ملف الحالة نفسه.

للبدء من الصفر دون استبدال جلسة سابقة، استخدم اسم ملف جديد:

```bash
python -u binance_cascade_hunter_dynamic_v2_paper.py --state paper_state_khaled_new.json
```

خيار `--reset` يمسح حساب **ملف الحالة المحدد** ويبدأ من 100؛ لا تستخدمه لاستعادة جلسة.

## التشغيل مع اللوحة المشتركة

`run_paper_live.py` ينشئ جلسة جديدة في كل تشغيل، إلا عند تمرير `--resume`. يرسل بيانات `Khaled` بهوية `khaled` من كتلة `dashboard` في baseline. يلزم رمز نشر صالح لهذه الهوية، يوفَّر محليًا في `CASCADE_DASHBOARD_TOKEN`؛ لا ترفع الرمز أو ملفات البيئة إلى Git. نجاح الاتصال لا يُفترض حتى يقبل الخادم التحديثات.

بعد تفعيل البيئة وتعيين رمز Khaled في الطرفية:

```bash
python -u run_paper_live.py
```

لاستعادة جلسة سابقة مع اللوحة:

```bash
python -u run_paper_live.py --resume paper_state_khaled.json
```

الربط لا يغيّر دخول الصفقات أو الخروج منها. يبقى `--legacy-dashboard` متاحًا لتوافق الواجهة فقط عند وجود إعداد Sites مستقل صالح. لم تُشغّل المحاكاة أو تُرسل بيانات للوحة ضمن تحديث الريبو.

## السجل وحفظ الحالة

- `strategy_positions` تحفظ المستويات الأصلية والحالية، وATR عند الدخول، وR:R، و`breakeven_armed` وحالة القص.
- `trades[].signal_id` يربط تنفيذ الدخول بسجل الإغلاق.
- `trades[].exit_detail` يحتوي جميع حقول التحليل المطلوبة: الاتجاه، والدخول، والوقف الأصلي والنهائي، والهدف، والنسب، وR:R، والتفعيل، وسبب وسعر الخروج، والربح، ومدة الصفقة، وATR، والرافعة، وحالة قص الوقف.
- `exit_detail.exit_reason` يستخدم `stop_loss/take_profit`. ويُفصّل `exit_attribution` الخروج إلى `stop_loss/take_profit/breakeven/trailing`. تبقى علامة `TP/SL` الخارجية متاحة لتوافق المستهلكين الحاليين.
- تعتمد المستويات على سعر التنفيذ الفعلي، وصافي الربح المسجل يشمل رسوم الطرفين. عند تعذر ATR يستخدم آخر قيمة صالحة ثم قيمة بديلة من baseline، ويُسجل مصدرها دون إضافة فلتر دخول.
- تُقبل الحالات السابقة ذات الإعدادات المتوافقة، وتُحدّث معلومات الخروج القديمة عند أول فحص. لا يمكن استعادة ATR تاريخي لم يكن مسجلًا.

## الاختبارات والفحص التاريخي

```bash
python -m pip install pytest
python -m pytest tests/test_tp_sl.py -q
python -m pytest -q
```

لفحص حسابات TP/SL على أرشيفات Binance الأصلية بعد تنزيلها:

```bash
python tools/validate_exit_history.py --data-dir /path/to/archives --months 2026-07 2026-08 2026-09 --output /tmp/exit_validation.json
```

النتائج المحفوظة في [historical_exit_validation.json](reports/historical_exit_validation.json) تشمل روابط المصادر وSHA-256. هذا فحص حسابي تاريخي، وليس صفقات منفذة أو Backtest للاستراتيجية. يلزم سجل دفتر أوامر تاريخي وتحديثات داخل الشمعة لإعادة الدخول نفسه دون تغيير شروطه.
