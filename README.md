# Khaled — النسخة المرجعية المعتمدة 3.0.3

بوت Binance USDT-M Futures بثلاثة أوضاع من إعداد واحد في [baseline.json](baseline.json): `exchange.mode = paper | testnet | mainnet`. **القيمة الحالية `paper`.** ريبو `Final` مستقل ولم يُعدّل.

**النسخة الحالية المعتمدة للمشروع: 3.0.3، بتاريخ 5 نوفمبر 2026.** تشمل آخر تعديلات TP/SL وطبقات التنفيذ والحماية، وهي المرجع الحالي للتطوير والمراجعة على `main`. جُمعت المراجعة في [تقرير واحد](reports/LIVE_READINESS.md)، والنسخ السابقة محفوظة في تاريخ Git.

**نطاق الاعتماد:** اعتماد الكود والاختبارات المحلية، وليس اعتماد تشغيل mainnet أو إثبات الربحية. نجحت 88 اختبارًا و9 اختبارات فرعية. لم يكتمل تشغيل testnet أو تأهيل الأداء؛ الوضع الحالي `paper`، وبوابات الأسبوعين والموافقة الصريحة بقيت كما هي.

## تشغيل Final وKhaled مع اللوحة المحلية من الصفر

لإعداد Ubuntu الظاهر في هذه الجلسة (`Final` في `/root/cascade-git` و`Khaled` في `/root/Khaled`):

```bash
cd /root/Khaled
git pull --ff-only origin main
python3 tools/run_comparison_dashboard.py --final-dir /root/cascade-git
```

افتح **http://127.0.0.1:8787** على الجهاز نفسه. المشغّل ينشئ جلسة مقارنة جديدة دائمًا، ويتحقق أن الحسابين يبدأان بـ100 USDT وصفر مراكز وتنفيذات. يشغّل نسختي البوت من مساريهما الحاليين؛ لا يحتاج CASCADE_DASHBOARD_TOKEN أو مفاتيح Binance أو Telegram، ويرفض أي مصدر مضبوط على testnet/mainnet. Ctrl+C يوقف المقارنة ويحفظ حسابي الجلسة.

إذا كانت اللوحة القديمة تعمل على المنفذ نفسه، أوقفها أولًا. لا يحذف المشغّل السجلات السابقة أو يوقف عمليات أخرى بالقوة. قد يستغرق التشغيل الأول وقتًا لتثبيت الاعتماديات في بيئة المقارنة المنفصلة.

تُستعاد أصول واجهة المقارنة المحلية وحدها من commit مثبت إلى `runtime/`، ولا يُستعاد أي كود بوت قديم. مداخل العمال تشير صراحة إلى Final الحالي وKhaled الحالي، وتعرض الواجهة إعدادات ATR الجديدة. النشر السحابي الاختياري في آخر README مسار آخر ولا يلزم لهذه اللوحة.

## طريقة التداول

| البند | السلوك |
|---|---|
| الإشارة | نفس cascade والحركة ±1.2% وحجم 3.5× وضغط أول 20 مستوى ±0.35 والتبريد 8 ثوانٍ |
| الهامش المستهدف | 10% من **equity الحالي**، بما يشمل الخسائر غير المحققة |
| الرافعة | 10×، مع ISOLATED في الأوضاع الحية |
| أقصى المراكز | 3 |
| TP/SL | نفس حسابات ATR الحالية: ATR ×1.5 للوقف، وهدف أكبر من ATR ×2.5 أو الوقف ×1.5 |
| حماية الوقف | القيد التقريبي قبل التصفية وسقف المخاطرة المخططة 3% مع الرسوم محفوظان؛ يُفحص سعر التصفية الفعلي في live أيضًا |
| Breakeven وTrailing | نفس التفعيل عند +0.6% وإزاحة 0.1% أو الرسوم، ثم تتبّع 1.2×ATR دون إرخاء |
| Time Stop | بعد 45 دقيقة إذا كانت الحركة المواتية أقل من 0.2%، بعد فحص TP/SL |
| التمويل | في live، إغلاق المراكز الدافعة لتمويل يتجاوز 0.05% خلال خمس دقائق من موعد Binance الفعلي |
| بداية mainnet بعد التأهيل فقط | 1% من الحجم المستهدف؛ نسبة الهامش الأساسية والرافعة لا تتغيران |

عند هامش 10% ورافعة 10×، وقف 0.8% يعادل مخاطرة 0.8% من equity قبل الرسوم. تظل معادلات ATR والوقف الديناميكي وسقف المخاطرة المخططة 3% كما هي. القفزات والانزلاق والتأخير قد تجعل الخسارة المحققة أكبر.

**حدود التعرض:** القيم 30% لكل اتجاه و50% إجمالًا تُقاس افتراضيًا على **الهامش**، لأن قياسها على القيمة الاسمية سيرفض أول مركز بقيمة تقارب 100% من equity. يمكن اختيار `exposure.basis = notional`، لكنه سيمنع الحجم الحالي. حد الارتباط يمنع ثالث مركز في المجموعة نفسها والاتجاه نفسه؛ لذلك قد تُرفض بعض الفرص. حساب الإشارة نفسه لم يتغير، ولا يوجد وعد بتطابق عدد الصفقات بعد تطبيق الحدود المطلوبة.

## التثبيت والتحديث

```bash
cd ~/Khaled
git pull --ff-only
python3 -m venv .venv

```

يتطلب Python 3.11+ على Linux. أوقف أي عملية سابقة قبل تحديث الكود. لا تستخدم حساب Futures مشتركًا مع بوت آخر أو تداول يدوي: المصالحة تفحص **كل الحساب** وقد تغلق المراكز غير المعروفة وتلغي الأوامر غير المملوكة.

## تشغيل paper

```bash
python -u run_bot.py
```

يحفظ الحالة افتراضيًا في `runtime/paper/state.json`. لا يحتاج مفاتيح Binance؛ لا تُنشأ أوامر حقيقية. المحاكاة تستخدم أسعار السوق العامة، ولا تحاكي التصفية الفعلية أو رسوم التمويل الفعلية.

الأوامر القديمة وواجهات `PaperExchange` و`PaperState` و`make_position` و`manage_exits` باقية للتوافق. اسم runner القديم يحتوي كلمة paper، لكنه يقرأ `exchange.mode` أيضًا؛ لا تعتمد على اسم الملف لتحديد البيئة.

## إعداد testnet محليًا

1. أنشئ بيانات Binance Futures التجريبية في حساب مخصص. يلزم وضع one-way، وsingle-asset USDT. البوت يرفض Hedge/Multi-Assets ويضبط ISOLATED و10× لكل رمز قبل الفتح.
2. تحقق من صلاحيات Futures فقط، وتعطيل السحب، وقائمة IP المسموحة لجهاز التشغيل. هذه ضوابط يراجعها المشغّل؛ سجل المراجعة المحلي ليس إثباتًا آليًا من Binance.
3. مرّر `BINANCE_API_KEY` و`BINANCE_API_SECRET` و`TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` في بيئة العملية فقط. لا تضع القيم في baseline أو Git أو المحادثة. Telegram إلزامي في testnet/mainnet ويُفحص تسليم رسالة بدء التشغيل قبل فتح الصفقات.
4. انسخ [نموذج سياسة المشغّل](docs/operator_policy.example.json) إلى `runtime/testnet/operator_policy.json`. القيم الافتراضية تمنع البدء. حدّثها بعد التحقق الفعلي، وضع تاريخ تدوير المفتاح بصيغة ISO مع timezone؛ بعد 90 يومًا يرفض البوت السجل القديم.
5. غيّر **`exchange.mode` فقط** من `paper` إلى `testnet`. عنوان REST الموثق حاليًا `https://demo-fapi.binance.com`، والـWebSocket التجريبي منفصل عن mainnet.
6. شغّل `python -u run_bot.py` على جهاز دائم التشغيل. ملفات الحالة والأوامر والسجلات منفصلة في `runtime/testnet/`. لا تستخدم `--reset` مع live.

لإدخال قيمة في Bash دون كتابتها حرفيًا في سجل الأوامر، يمكن تكرار النمط التالي لكل متغير:

```bash
read -r -s -p "Binance TESTNET API key: " BINANCE_API_KEY
export BINANCE_API_KEY
```

لتحضير سجل السياسة قبل تحريره محليًا:

```bash
mkdir -p runtime/testnet
cp docs/operator_policy.example.json runtime/testnet/operator_policy.json
```

بيانات الإعداد تبقى محلية. لم تُضبط مفاتيح أو Telegram ولم يبدأ testnet ضمن تحديث الريبو.

## بوابات mainnet والتدرج

اختيار `mainnet` وحده **لا يكفي**. البوت يرفض إنشاء عميل التنفيذ قبل وجود:

- 14 يومًا فعليًا من المراقبة على testnet، منها 7 أيام متصلة؛ إعادة تشغيل العملية تكسر نافذة الاتصال المستمر.
- 100 صفقة مغلقة على الأقل، مع شروط الانزلاق وSharpe وDrawdown والعلوق، وصفر حوادث تقنية أو اختلافات مصالحة في سجل التأهيل.
- شهادة موافقة صريحة محلية مرتبطة بـSHA-256 لأدلة testnet وبصمة الإعدادات والكود، في `rollout.approval_file`؛ لا توجد شهادة موافقة منشأة في هذا الريبو.
- سياسة مشغّل صالحة لـmainnet، ومفاتيح البيئة الصحيحة، وتنبيهات عاملة، ومصالحة نظيفة، وعدم وجود KillSwitch معلّق.

البداية 1% من الحجم المستهدف. كل زيادة تحتاج مراجعة مستقلة ودليلًا فعليًا عن 14 يومًا إضافية وموافقة مرتبطة به في `rollout.scale_approval_file`. الحد الأعلى لكل خطوة هو ضعفا النسبة السابقة، حتى 100% من المستهدف. تُستهلك الموافقة مرة واحدة عند إعادة التشغيل؛ **لا يتضاعف التعرض الممول تلقائيًا أثناء التشغيل**.

تغيير الكود أو إعدادات الاستراتيجية يبطل بصمة التأهيل. ملفات الأدلة سجلات محلية للمشغّل وليست إثباتًا مستقلًا مقاومًا للتلاعب. لا تُعتبر قيم JSON يدوية بديلًا عن التشغيل الحقيقي والمراجعة.

لقراءة الوضع الحالي دون اتصال أو أوامر أو موافقات:

```bash
python tools/readiness_report.py
```

## الحوادث وإعادة التشغيل

KillSwitch يقفل الدخول عند حد خسارة اليوم 5%، أو 4 خسائر متتالية، أو توقف البيانات 30 ثانية، أو 5 أخطاء API خلال نافذة دقيقة فعلية، أو اتساع spread إلى خمسة أضعاف متوسطه. خسارة اليوم تشمل أيضًا تراجع equity غير المحقق وتُقارن بمرجع بداية اليوم.

المراقب المستقل يقفل الدخول حتى إن كان طلب REST بطيئًا. التنفيذ يحاول إغلاق المراكز بأوامر market ويُلغي الأوامر، ويسجل الحدث ويرسل تنبيهًا. إذا تعذر الإغلاق، تبقى أوامر الحماية للمراكز المتبقية ويستمر القفل والمحاولات. لا يمكن ضمان تنفيذ الإغلاق أو تسليم التنبيه أثناء انقطاع البورصة أو الشبكة.

- كل حساب حي له قفل عملية، والحالة تحفظ القفل الأمني عبر restart.
- المصالحة عند البدء ودوريًا تشمل المراكز خارج قائمة المسح، والمراكز الوهمية، والحجم والسعر والاتجاه، والأوامر غير المعروفة، وأوامر الحماية المفقودة. الاختلاف يقفل التداول ويحتاج مراجعة.
- الإغلاق المعروف بأمر SL/TP أصلي على البورصة يُتبنى ويسجل كخروج طبيعي، مع إلغاء الأمر المقابل.
- عند timeout/503 بعد الإرسال، يُستعلم بنفس client ID. تُتبنى النتيجة الموجودة. الغياب غير المؤكد **لا يؤدي إلى إعادة إرسال عمياء**. المحاولات ذات ID جديد محصورة في رفض مؤكد قابل للإعادة.
- إيقاف العملية الحية يحاول تسطيح المراكز ويحفظ قفلًا يحتاج مراجعة قبل الاستئناف.

بعد إيقاف العملية ومراجعة الحادث والتأكد من خلو الحالة المحفوظة من المراكز:

```bash
python tools/reset_safety.py --state runtime/testnet/state.json --reviewed
```

هذا يعيد القفل المحلي فقط؛ المصالحة وباقي البوابات تبقى إلزامية. لا تمسح الحالة أو الأدلة لتجاوز حادث.

## الأوامر والحماية والتنبيهات

أوامر السوق عبر Futures REST، والحماية الأصلية عبر Futures Algo API. تعديل `PUT /fapi/v1/order` يدعم LIMIT؛ لذلك تحديث SL الشرطي هنا يضع أمرًا جديدًا ويؤكده ويحفظه قبل إلغاء القديم. تبقى الأوامر reduce-only، ويُحافَظ على الوقف السابق إذا فشل البديل. هذا تداخل حماية مؤقت وليس استدعاء cancelReplace ذريًا غير مدعوم.

الطلبات محددة بالمعدل والوزن وعدد الأوامر؛ 429/418 يفرضان تهدئة مشتركة مع احترام Retry-After. السجلات لا تتضمن المفاتيح أو تواقيع الطلبات أو نصوص أخطاء HTTP الحساسة.

تنبيهات Telegram تشمل فتح وإغلاق الصفقات، وسبب وصافي الإغلاق، والحوادث، وWebSocket بعد 10 ثوانٍ، وأخطاء API المتكررة، والمصالحة، والانزلاق المرتفع. في 00:00 UTC يرسل تقرير اليوم السابق، مع equity الحالي ومقاييس التأهيل المتاحة. التقرير من داخل العملية؛ يتوقف إذا توقفت العملية.

تُحفظ الأحداث في `runtime/<mode>/journal/events.log` و`kill_events.log`. تحفظ الحالة `trades[].exit_detail`، ومعلومات الانزلاق المتوقع/الفعلي، والرسوم. الإغلاق الجزئي يُجمع قبل احتساب صافي المركز النهائي من التنفيذات ورسومها. التمويل المدفوع ينعكس في equity الفعلي، ولا يُوزع حاليًا على صافي كل سجل صفقة. يدعم الإصدار محاسبة الرسوم المدفوعة بـUSDT؛ اختلاف عملة الرسوم أو نقص سجلات التنفيذ يوقف التشغيل للمراجعة.
