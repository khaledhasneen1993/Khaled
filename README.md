# Khaled — Cascade Hunter V2

نسخة `Khaled` من الأساس **2.0.0** مع تحديث TP/SL بتاريخ **4 نوفمبر 2026**. محاكاة ورقية ببيانات Binance USDT-M المباشرة. أمر التشغيل الأساسي هو `run_paper_live.py` مع لوحة متابعة خاصة.

## الإعدادات المعتمدة

| الإعداد | القيمة |
|---|---|
| الرصيد الابتدائي للجلسة الجديدة | 100 USDT افتراضي |
| هامش كل صفقة | 10% من رصيد المحفظة الحالي |
| الرافعة | 50× |
| أقصى المراكز المفتوحة | 3 |
| وقف الخسارة | ATR × 1.5، مقيد بالتصفية التقريبية ومخاطرة مخططة ≤3% من equity مع الرسوم |
| جني الربح | الأكبر من ATR × 2.5 ومسافة الوقف × 1.5 |
| شرط الحركة | تتجاوز ±1.2% بين الإغلاق الحالي وإغلاق قبل دقيقتين |
| شرط الحجم | أكبر من 3.5× متوسط الشموع `[-15:-3]` |
| ضغط دفتر الأوامر | أكبر من 0.35 للشراء، وأقل من −0.35 للبيع |
| قائمة المراقبة | أعلى 40 عقدًا مؤهلًا بالسيولة، بحجم يومي أدنى 15 مليون USDT |
| متابعة الإشارات | مستمرة بتحديثات WebSocket |
| تحديث قائمة العملات | كل 600 ثانية؛ ليس انتظارًا بين فحوص الإشارات |
| مراقبة الخروج | كل 8 ثوانٍ |
| تبريد الدخول للعملة | 8 ثوانٍ |
| الرسوم الافتراضية | 0.05% لكل تنفيذ |

الإعدادات الموثقة موجودة أيضًا في `baseline.json`. القيم التنفيذية في `binance_cascade_hunter_dynamic_v2.py`، وتتحقق الاختبارات من تطابقها مع النسخة المعتمدة. مثلًا: محفظة 100 USDT تعطي هامشًا يقارب 10 USDT وقيمة مركز تقارب 500 USDT قبل التقريب والرسوم.

## التثبيت والتحديث على تيرمكس / أوبونتو

داخل أوبونتو، من نسخة المستودع الموجودة:

```bash
cd ~/Khaled
python3 -m venv .venv
source .venv/bin/activate

```

يتطلب Python 3.11 أو أحدث. إذا كانت المحاكاة تعمل، أوقفها بـ Ctrl+C وانتظر ظهور مؤشر الأوامر قبل التحديث. لا تشغّل أكثر من عملية على ملف الحالة نفسه.

## تفاصيل الصفقات والتصدير

اللوحة تعرض الجلسات، والرصيد، وقيمة المحفظة، والمراكز المفتوحة، وأسعار وأوقات الدخول والخروج، والكمية والرسوم والربح، وسبب الدخول والخروج. يمكن تنزيل الصفقات بصيغة CSV.

يحفظ السجل قياسات الحركة والحجم وضغط الدفتر عند الدخول، وسبب TP/SL وسعر الرصد عند الخروج. سعر تنفيذ المحاكاة يُجلب منفصلًا وقد يختلف عن سعر الإشارة أو رصد الخروج. صافي الصفقة المغلقة يطرح رسوم الدخول والخروج معًا؛ ربح المركز المفتوح غير محقق. تظهر قياسات السجلات القديمة التي لم تُحفظ كبيانات غير متوفرة.

## الاختبارات وحدود المحاكاة

```bash
python -m pip install pytest
python -m pytest -q
python run_paper_live.py --help
```

الاختبارات تستخدم بيانات وخدمات وهمية للتحقق من المنطق والحفظ والرفع؛ ليست نتائج تداول أو اختبارًا تاريخيًا. لا يحاكي النموذج التصفية أو هامش الصيانة أو التمويل أو الانزلاق. قيم الوقف والهدف الثابتة القديمة بقيت للتوافق فقط؛ مسار الفتح الحالي يستخدم كتل `tp_sl` و`atr` و`exit` الجديدة. التصفية هنا تقريبية ومعامل MMR ثابت قابل للضبط؛ لا يمثل ذلك محاكاة تصفية فعلية لكل عملة وشريحة. يتطلب استمرار المحاكاة بقاء تيرمكس والاتصال بالسوق قيد التشغيل.


## إدارة الخروج الجديدة

- حساب ATR من آخر 15 شمعة دقيقة متاحة دون تعديل شروط الإشارة. عند انقطاعه يستخدم آخر ATR معروف، ثم `fallback_atr_pct` من baseline، ويسجل المصدر دون رفض الإشارة.
- جميع المستويات مبنية على **سعر التنفيذ الفعلي**. يُقص الوقف قبل التصفية التقريبية، مع احتياط مضاعف دقيق للـshort وحدود التقريب العشري.
- مخاطرة الخسارة المخططة تشمل رسوم الدخول والخروج وتبقى ≤3% من equity عند فتح الصفقة. تبقى الكمية والهامش والرافعة كما هي. بسبب هامش 10% ورافعة 50×، يتقدم هذا القيد على حد ATR الأدنى 0.8%؛ الوقف النموذجي نحو 0.5% مع الرسوم الافتراضية. لا يضمن الوقف سقف الخسارة المحققة عند القفزات أو التأخير.
- Breakeven عند حركة مواتية 0.6%، بإزاحة 0.1% أو ما يغطي الرسوم الفعلية إذا كان أكبر. Trailing بمسافة 1.2×ATR ولا يرخّي الوقف. كلاهما يغير الوقف فقط؛ `manage_exits(self)` تبقى مسؤولة عن الإغلاق، والوقف له الأولوية.
- `Position` توسع dict القائمة دون كسر مفاتيح `buy/sell` و`sl/tp`. تُحفظ حالة الوقف والتفعيل والقياسات في JSON. تُرقّى المراكز القديمة قبل فحص الخروج الأول، وتُعلّم `legacy_migrated`؛ ATR القديم غير المسجل لا يمكن استعادته بدقة.
- كل إغلاق يسجل الحقول المطلوبة في `trades[].exit_detail`. يبقى `exit_reason` الخارجي القديم `TP/SL` متوافقًا، أما `exit_detail.exit_reason` فهو `take_profit/stop_loss`. حقل `exit_attribution` يفصل `breakeven/trailing` للتحليل دون إنشاء آلية خروج إضافية.
- لا توجد إضافة خروج زمني أو signal decay أو تغيير لقواعد الدخول. `active_exit` داخل إعدادات الحالة يوضح الإعدادات الفعلية بدل الاعتماد على الثوابت القديمة.

نتائج الفحص وحدود القبول: [reports/TP_SL_REPORT.md](reports/TP_SL_REPORT.md).

لإعادة فحص حسابات الخروج على أرشيفات Binance الشهرية الأصلية:

```bash
python tools/validate_exit_history.py --data-dir /path/to/archives --months 2026-07 2026-08 2026-09 --output /tmp/historical_exit_validation.json
```

هذا فحص حسابي تاريخي، وليس backtest للاستراتيجية. يلزم سجل دفتر الأوامر لأول 20 مستوى مع تحديثات الشموع أثناء تكونها لإعادة الدخول الأصلي دون افتراضات. لا يوجد تقرير ربحية معتمد بعد هذا التعديل.

ربط اللوحة الموروث من Final لم يتغير ضمن مهمة TP/SL؛ `CloudPublisher` ما زال يستخدم هوية `final`. التشغيل المحلي الاختياري أعلاه لا ينشر للوحة. لم يُشغّل أي بوت أو ناشر أثناء هذا التحديث.
