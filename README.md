# Cascade Hunter Khaled

النسخة الأساسية المعتمدة: **2.2.0-PAAE**، بتاريخ **3 نوفمبر 2026**. محاكاة ورقية ببيانات Binance USDT-M المباشرة. أمر التشغيل الأساسي هو `bash run_dashboard.sh` للوحة Termux المحلية.

## الإعدادات المعتمدة

| الإعداد | القيمة |
|---|---|
| الرصيد الابتدائي للجلسة الجديدة | 100 USDT افتراضي |
| هامش كل صفقة | 10 USDT أساسًا، و5 USDT في وضع Survival، مع تقريب الكمية لدقة السوق |
| الرافعة | 10× |
| أقصى المراكز المفتوحة | 6 |
| وقف الخسارة | −2.8% من سعر التنفيذ الفعلي للدخول |
| تقليل الخسارة | خروج كامل عند −1% خلال أول 25 ثانية، وبعدها إغلاق نصف الكمية عند −1.5% وتضييق الوقف فورًا |
| جني الربح | التفعيل ← الوقف: ‎+0.8% ← 0%، ‎+1.2% ← +0.5%، ‎+1.8% ← +1%، ‎+2.5% ← +1.5%، ‎+3.5% ← +2.2%، ‎+5% ← +3% |
| شرط الحركة | تتجاوز ±1.2% بين الإغلاق الحالي وإغلاق قبل دقيقتين |
| شرط الحجم | أكبر من 3.5× متوسط الشموع `[-15:-3]` |
| ضغط دفتر الأوامر | أكبر من 0.35 للشراء، وأقل من −0.35 للبيع |
| قائمة المراقبة | أعلى 40 عقدًا مؤهلًا بالسيولة، بحجم يومي أدنى 15 مليون USDT |
| متابعة الإشارات | مستمرة بتحديثات WebSocket |
| تحديث قائمة العملات | كل 600 ثانية؛ ليس انتظارًا بين فحوص الإشارات |
| مراقبة الخروج | كل 8 ثوانٍ |
| تبريد الدخول للعملة | 8 ثوانٍ |
| الرسوم الافتراضية | 0.05% لكل تنفيذ |

الإعدادات الموثقة موجودة أيضًا في `baseline.json`. القيم التنفيذية في `binance_cascade_hunter_dynamic_v2.py`، وتتحقق الاختبارات من تطابقها مع النسخة المعتمدة. قيمة المركز المستهدفة 100 USDT بهامش 10 USDT ورافعة 10×، وتنخفض إلى 50 USDT في وضع Survival. الرسوم إضافية، ويُرفض الدخول إذا لم يكفِ الهامش الحر.

النسب محسوبة من سعر تنفيذ الدخول وتُعكس للبيع. بعد الإغلاق الجزئي، يُختار الوقف الأشد بين −1.8% من الدخول ومسافة 0.6% خلف سعر الرصد. عند تعافي الجزء المتبقي إلى +0.4% يضيق الوقف إلى +0.05% من الدخول إن كان أشد. هذا المستوى لا يعوّض بالضرورة خسارة الجزء المغلق والرسوم. الوقف يتقدم باتجاه الربح فقط.

تُرفض الإشارات دون قوة 0.025. بعد صافي خسارة تُمنع إعادة الدخول على الرمز لمدة 900 ثانية. يخفض Survival الهامش بعد ثلاث خسائر متتالية أو تراجع قيمة الحساب 5% عن أعلى قيمة مرصودة. تُحفظ بيانات المخاطر مع الجلسة.

## تشغيل Final وKhaled فقط على لوحة تيرمكس

من داخل Ubuntu في Termux، بعد إيقاف اللوحة إن كانت تعمل:

```bash
cd ~/Khaled
git pull --ff-only origin main
bash run_dashboard.sh --fresh
```

التثبيت الأول: `git clone https://github.com/khaledhasneen1993/Khaled.git ~/Khaled`.
يلزم Python 3.11+ مع venv وGit. يثبت السكربت الاعتماديات، ويجلب مصدر Final main في نسخة محلية منفصلة داخل `.runtime/repos/Final`، ثم يفتح نفس واجهة المتابعة المحلية على **http://127.0.0.1:8787**. لا يحتاج رمز لوحة سحابية.

- `--fresh`: حسابان مستقلان، كل منهما 100 USDT وصفر مراكز وتنفيذات عند البداية؛ تُحفظ الجلسات السابقة دون حذف.
- `bash run_dashboard.sh`: يستأنف آخر جلسة مختارة ورصيدها ومراكزها. تُرقّى حالة Khaled المحفوظة من الإصدار السابق عند الاستئناف.
- Ctrl+C يوقف البوتين ويحفظ حالتيهما؛ أزرار اللوحة توقف أو تستأنف كل بوت منفصلًا.
- Final يعمل بإعداداته الأصلية؛ Khaled يعمل بإعداداته المذكورة أعلاه. لم يتغير مصدر Final.
- سجل الصفقات لا يحتسب إغلاق النصف كصفقة مكتملة؛ يجمع رسوم وخسائر الجزء الأول مع الخروج النهائي. كل التنفيذات متاحة للتصدير.
- كل عملية تحمل مصدرًا مستقلًا وملف حالة مستقلًا؛ اختيار الجلسة محفوظ في `.runtime/dashboard-accounts.json`.
- إن كان المنفذ 8787 مشغولًا، أوقف العملية التي تستخدمه قبل التشغيل.

لإبقاء الجلسة متاحة عند إغلاق الطرفية: شغّل `tmux new -s final-khaled` داخل Ubuntu قبل أمر التشغيل؛ للفصل Ctrl+B ثم D، وللعودة `tmux attach -t final-khaled`.

فحص واجهة التحكم: `python -m unittest discover -s dashboard/tests -v`.

## تفاصيل الصفقات والتصدير

اللوحة تعرض الجلسات، والرصيد، وقيمة المحفظة، والمراكز المفتوحة، وأسعار وأوقات الدخول والخروج، والكمية والرسوم والربح، وسبب الدخول والخروج. يمكن تنزيل الصفقات بصيغة CSV.

يحفظ السجل قياسات الحركة والحجم وضغط الدفتر عند الدخول، وسبب `SL` أو `FAST_ADVERSE` أو `PARTIAL_SL` أو `POST_PARTIAL` أو `BE_AFTER_PARTIAL` أو `TRAILING_SL` وسعر الرصد عند الخروج. سعر تنفيذ المحاكاة يُجلب منفصلًا وقد يختلف عن سعر الإشارة أو رصد الخروج. صافي الصفقة المغلقة يطرح رسوم الدخول والخروج معًا؛ ربح المركز المفتوح غير محقق. تظهر قياسات السجلات القديمة التي لم تُحفظ كبيانات غير متوفرة.

## التشغيل المحلي الاختياري

لتشغيل Khaled منفردًا داخل Ubuntu:

```bash
cd ~/Khaled
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -u binance_cascade_hunter_dynamic_v2_paper.py
```

هذا الأمر يستعيد `paper_state_dynamic_v2.json` تلقائيًا إن وُجد. يمكن تحديد ملف مختلف باستخدام `--state`. خيار `--reset` يستبدل حالة الملف المختار بحساب جديد؛ لا تستخدمه لاستعادة محاكاة سابقة.

## الاختبارات وحدود المحاكاة

```bash
python -m unittest discover -s tests -v
python -m unittest discover -s dashboard/tests -v
```

الاختبارات تستخدم بيانات وخدمات وهمية للتحقق من المنطق والحفظ والرفع؛ ليست نتائج تداول أو اختبارًا تاريخيًا. لا يحاكي النموذج التصفية أو هامش الصيانة أو التمويل أو الانزلاق. وقف 2.8% هو نسبة **السعر**. التنفيذ ورقي بسعر السوق المرصود وقد يتجاوز مستوى الستوب بسبب الفجوات وتأخير الرصد. يتطلب استمرار المحاكاة بقاء تيرمكس والاتصال بالسوق قيد التشغيل.
