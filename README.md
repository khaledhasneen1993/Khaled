# Cascade Hunter Khaled

النسخة الأساسية المعتمدة: **2.1.0**، بتاريخ **2 نوفمبر 2026**. محاكاة ورقية ببيانات Binance USDT-M المباشرة. أمر التشغيل الأساسي هو `run_paper_live.py` مع لوحة متابعة خاصة.

## الإعدادات المعتمدة

| الإعداد | القيمة |
|---|---|
| الرصيد الابتدائي للجلسة الجديدة | 100 USDT افتراضي |
| هامش كل صفقة | 10 USDT ثابتة، مع تقريب الكمية لدقة السوق |
| الرافعة | 10× |
| أقصى المراكز المفتوحة | 6 |
| وقف الخسارة | −3% من سعر التنفيذ الفعلي للدخول |
| تقليل الخسارة | إغلاق نصف الكمية المتاحة مرة واحدة عند −1.5%؛ الباقي محمي عند −3% |
| جني الربح | ستوب متدرج: +1% ← ستوب +0.5%؛ +1.5% ← +1%؛ +2% ← +1.5%، وهكذا |
| شرط الحركة | تتجاوز ±1.2% بين الإغلاق الحالي وإغلاق قبل دقيقتين |
| شرط الحجم | أكبر من 3.5× متوسط الشموع `[-15:-3]` |
| ضغط دفتر الأوامر | أكبر من 0.35 للشراء، وأقل من −0.35 للبيع |
| قائمة المراقبة | أعلى 40 عقدًا مؤهلًا بالسيولة، بحجم يومي أدنى 15 مليون USDT |
| متابعة الإشارات | مستمرة بتحديثات WebSocket |
| تحديث قائمة العملات | كل 600 ثانية؛ ليس انتظارًا بين فحوص الإشارات |
| مراقبة الخروج | كل 8 ثوانٍ |
| تبريد الدخول للعملة | 8 ثوانٍ |
| الرسوم الافتراضية | 0.05% لكل تنفيذ |

الإعدادات الموثقة موجودة أيضًا في `baseline.json`. القيم التنفيذية في `binance_cascade_hunter_dynamic_v2.py`، وتتحقق الاختبارات من تطابقها مع النسخة المعتمدة. قيمة المركز المستهدفة 100 USDT بهامش 10 USDT ورافعة 10×، مستقلة عن رصيد المحفظة. الرسوم إضافية، ويُرفض الدخول إذا لم يكفِ الهامش الحر.

النسب هي حركة السعر لصالح الصفقة، وليست عائد الهامش بعد الرافعة، وتُعكس للصفقات القصيرة. الستوب يتحرك في اتجاه الربح فقط على درجات 0.5% ولا يُخفض عند تراجع السعر؛ لا يوجد إغلاق عند هدف ربح ثابت. ينطبق نفس التدرج على النصف المتبقي بعد التعافي. إذا قفز السعر مباشرة عبر −3% تُغلق الكمية المتبقية كاملة. تقليل النصف يخضع لدقة كمية السوق. تُحفظ حالة التقليل والتدرج مع كل دورة خروج.

## تشغيل Final وKhaled فقط على لوحة تيرمكس

من داخل Ubuntu في Termux، بعد إيقاف اللوحة القديمة:

```bash
cd ~/Khaled
git pull --ff-only origin main
bash run_dashboard.sh --fresh
```

التثبيت الأول: `git clone https://github.com/khaledhasneen1993/Khaled.git ~/Khaled`.
يلزم Python 3.11+ مع venv وGit. يثبت السكربت الاعتماديات، ويجلب مصدر Final main في نسخة محلية منفصلة داخل `.runtime/repos/Final`، ثم يفتح نفس واجهة المتابعة المحلية على **http://127.0.0.1:8787**. لا يحتاج رمز لوحة سحابية.

- `--fresh`: حسابان مستقلان، كل منهما 100 USDT وصفر مراكز وتنفيذات عند البداية؛ تُحفظ الجلسات السابقة دون حذف.
- `bash run_dashboard.sh`: يستأنف آخر جلسة مختارة ورصيدها ومراكزها.
- Ctrl+C يوقف البوتين ويحفظ حالتيهما؛ أزرار اللوحة توقف أو تستأنف كل بوت منفصلًا.
- Final يعمل بإعداداته الأصلية؛ Khaled يعمل بإعداداته المذكورة أعلاه. لم يتغير مصدر Final.
- سجل الصفقات لا يحتسب إغلاق النصف كصفقة مكتملة؛ يجمع رسوم وخسائر الجزء الأول مع الخروج النهائي. كل التنفيذات متاحة للتصدير.
- كل عملية تحمل مصدرًا مستقلًا وملف حالة مستقلًا؛ اختيار الجلسة محفوظ في `.runtime/dashboard-accounts.json`.
- إن كان المنفذ 8787 مشغولًا، أوقف اللوحة القديمة أولًا؛ السكربت لا يوقف عمليات أخرى تلقائيًا.

لإبقاء الجلسة متاحة عند إغلاق الطرفية: شغّل `tmux new -s final-khaled` داخل Ubuntu قبل أمر التشغيل؛ للفصل Ctrl+B ثم D، وللعودة `tmux attach -t final-khaled`.

فحص واجهة التحكم: `python -m unittest discover -s dashboard/tests -v`.

## التثبيت والتحديث على تيرمكس / أوبونتو

لأول تثبيت: `git clone https://github.com/khaledhasneen1993/Khaled.git ~/Khaled`. نسخة Final الأصلية مستقلة ولم تُعدّل.

داخل أوبونتو، من نسخة المستودع الموجودة:

```bash
cd ~/Khaled
python3 -m venv .venv
source .venv/bin/activate
git pull --ff-only
python -m pip install -r requirements.txt
```

يتطلب Python 3.11 أو أحدث. إذا كانت المحاكاة تعمل، أوقفها بـ Ctrl+C وانتظر ظهور مؤشر الأوامر قبل التحديث. لا تشغّل أكثر من عملية على ملف الحالة نفسه.

## تشغيل Khaled

رابط اللوحة الواحدة للبوتين: https://coamowlsyuqbxngijxsu.supabase.co/functions/v1/cascade-dashboard

التكامل يرسل حالة المحفظة والمراكز والتنفيذات وأسباب الدخول والخروج كل 10 ثوانٍ. لا يحتاج ملف `dashboard-config.json` القديم عند استخدام اللوحة الموحدة. التكامل الموروث مع اللوحة يرسل باسم `final`؛ لا تستخدم رمز Final القديم مع البوتين معًا لأن التحديثات قد تتداخل. لتشغيل النسخة محليًا دون لوحة استخدم الأمر في القسم التالي. خزّن رمز الربط في متغير البيئة المحلي `CASCADE_DASHBOARD_TOKEN` ولا ترفعه إلى GitHub أو تضعه في ملف متتبع.

```bash
cd ~/Khaled
source .venv/bin/activate
set -a; source .dashboard.env; set +a
python -u run_paper_live.py 2>&1 | tee -a live-paper-live.log
```

عند ظهور `COMBINED DASHBOARD TELEMETRY ENABLED` يكون إرسال البيانات مفعّلًا. إيقاف البوت بـ Ctrl+C يحفظ الحالة ويرسل حالة التوقف إن أمكن. لا تشغّل أكثر من عملية على ملف الحالة نفسه.

## تفاصيل الصفقات والتصدير

اللوحة تعرض الجلسات، والرصيد، وقيمة المحفظة، والمراكز المفتوحة، وأسعار وأوقات الدخول والخروج، والكمية والرسوم والربح، وسبب الدخول والخروج. يمكن تنزيل الصفقات بصيغة CSV.

يحفظ السجل قياسات الحركة والحجم وضغط الدفتر عند الدخول، وسبب SL / PARTIAL_SL / TRAILING_SL وسعر الرصد عند الخروج. سعر تنفيذ المحاكاة يُجلب منفصلًا وقد يختلف عن سعر الإشارة أو رصد الخروج. صافي الصفقة المغلقة يطرح رسوم الدخول والخروج معًا؛ ربح المركز المفتوح غير محقق. تظهر قياسات السجلات القديمة التي لم تُحفظ كبيانات غير متوفرة.

## التشغيل المحلي الاختياري

لتشغيل V2 نفسها دون نشر تحديثات للوحة:

```bash
python -u binance_cascade_hunter_dynamic_v2_paper.py 2>&1 | tee -a live-paper-v2.log
```

هذا الأمر يستعيد `paper_state_dynamic_v2.json` تلقائيًا إن وُجد. يمكن تحديد ملف مختلف باستخدام `--state`. خيار `--reset` يستبدل حالة الملف المختار بحساب جديد؛ لا تستخدمه لاستعادة محاكاة سابقة.

## تنظيم المشروع

| الملف | الدور |
|---|---|
| `run_paper_live.py` | التشغيل الأساسي وإرسال التحديثات الخاصة |
| `binance_cascade_hunter_dynamic_v2_paper.py` | حساب V2 والتشغيل المحلي الاختياري |
| `binance_cascade_hunter_dynamic_v2.py` | منطق الاستراتيجية وإعداداتها |
| `continuous_scanner.py` | الإشارات المستمرة وتحديث قائمة العملات |
| `paper_runtime.py` | دورة التشغيل وربط الاستراتيجية بالمحاكاة |
| `paper_account.py` | التنفيذ الافتراضي والرصيد وحفظ الحالة |
| `baseline.json` | تعريف النسخة والإعدادات المعتمدة |
| `tests/` | اختبارات النسخة الأساسية |

مصدر لوحة Sites محفوظ في مستودع استضافة مستقل؛ هذا المستودع يحتوي البوت والمرسل وتعليمات الربط. ملفات الحالة والسجلات ورمز الربط محلية ولا تُرفع إلى GitHub. تحديث المشروع لا يحذف جلسات الهاتف. تبقى النسخة الأصلية متاحة في مستودع Final.

## الاختبارات وحدود المحاكاة

```bash
python -m unittest discover -s tests -v
python run_paper_live.py --help
```

الاختبارات تستخدم بيانات وخدمات وهمية للتحقق من المنطق والحفظ والرفع؛ ليست نتائج تداول أو اختبارًا تاريخيًا. لا يحاكي النموذج التصفية أو هامش الصيانة أو التمويل أو الانزلاق. وقف 3% هو نسبة **السعر**. التنفيذ ورقي بسعر السوق المرصود وقد يتجاوز مستوى الستوب بسبب الفجوات وتأخير الرصد. يتطلب استمرار المحاكاة بقاء تيرمكس والاتصال بالسوق قيد التشغيل.
